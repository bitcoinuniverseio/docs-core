Every image on this page is the running product at
`www.bitcoinuniverse.io`, captured by a script that visits the public origin,
waits for each route to render rather than its skeleton, declines optional
storage, and connects no wallet. None of them is a mock.

## Home

The first screen states how many protocols this build serves, counted from the
same registry that builds the routes, and offers four next steps. Nothing on it
needs a wallet.

## Protocol coverage

One page lists what this build serves, grouped by family, with the index and
the market for each row. The counts are computed from the same registry that
builds the navigation, so the number on the page is the number of protocols
the application can actually open.

<figure class="shot">
  <Image src={coverageLight} alt="The protocol coverage page: totals for protocols, families, chains, and how many have an index, then every row grouped by family with links to its index and its market, and a read source named on the rows the browser fetches elsewhere." widths={[420, 840, 1440]} sizes="(max-width: 60rem) 100vw, 55rem" />
  <figcaption>Coverage, light theme.</figcaption>
</figure>

<figure class="shot">
  <Image src={coverageDark} alt="The same protocol coverage page in dark theme." widths={[420, 840, 1440]} sizes="(max-width: 60rem) 100vw, 55rem" />
  <figcaption>Coverage, dark theme.</figcaption>
</figure>

That page and the [support matrix](/docs-core/protocols/support-matrix/) answer
different questions. Coverage says what Core *reads*. The matrix says what Core
can *do*.

## A market

Each protocol family has a market with the same anatomy: a family picker, the
period the figures cover, a searchable table, and an activity feed. A figure
the reader did not return is a dash, never a zero.

## A market whose reader failed

This is the capture worth studying. When a reader cannot be reached, the market
says exactly that and offers a retry. It never presents a failed read as an
empty market.

<figure class="shot">
  <Image src={marketsRunes} alt="The Runes market showing a message that the order book did not answer so the market could not be read, with a retry link, and a table in a Market unavailable state rather than an empty table." widths={[420, 840, 1440]} sizes="(max-width: 60rem) 100vw, 55rem" />
  <figcaption>
    Unavailable, not empty. Compare it with a market that answered and had
    nothing listed: that one says "nothing listed" and offers no retry, because
    retrying would not change the answer.
  </figcaption>
</figure>

## What is not pictured here

Screens that need a connected wallet are described in words rather than shown,
because a real capture of them would contain someone's holdings and a mock
would be an invention. The
[Portfolio](/docs-core/portfolio/portfolio/) and
[market task](/docs-core/markets/buy/) pages describe those interfaces
precisely instead.
